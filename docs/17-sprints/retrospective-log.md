What we changed about how we work, and whether it helped. **This log has no entries yet, honestly —**
Sprint 01 has not run (per [sprint-01.md](sprint-01.md), dates are set at Phase 18 kickoff), and per
this phase's own rule, a retrospective that produces only sentiment is cancelled, not held for its
own sake. Fabricating a first entry here would be inventing an outcome for work that has not
happened, which this documentation set has consistently refused to do elsewhere (see, e.g.,
[capacity-model.md](../16-milestones/capacity-model.md)'s refusal to guess a capacity number).

## Entry format

```markdown
### Sprint NN retrospective — <date>

**What surprised us:** <a concrete fact learned, not a feeling>

**What we're changing:** <a specific, checkable change to cadence, template, backlog estimation,
or process — or explicitly "nothing, this sprint went as planned," which is itself a valid,
loggable outcome>

**Did the last change help?** <checked against the sprint(s) since it was made — retrospectives
review their own prior predictions, not only generate new ones>
```

## Why this log exists even though it starts empty

Per this phase's rule, a retrospective must change something concrete or it is cancelled — logging
*only* the retrospectives that produced a real change (never a blank "nothing to report" filler
entry) is what keeps this document a useful record of this project's actual process evolution rather
than a diary. The first real entry lands here the moment Sprint 01 closes and either does or does
not surface something worth changing — both are valid, neither is invented ahead of time.
